# 数据获取说明

## 📊 数据获取流程

### 1. DailySummaryCard.vue - 今日热量摘要

**数据来源**: `/api/stats/daily-summary`

**获取的数据**:
- `intake`: 今日摄入热量（从 FoodRecord 中 type='intake' 的记录累加）
- `exercise`: 今日运动消耗（从 FoodRecord 和 ExerciseRoute 两个数据源合并）
- `baseMetabolism`: 基础代谢估算（根据用户身体数据计算）
- `netCalories`: 净热量 = 摄入 - 运动消耗 - 基础代谢估算

**后端查询逻辑**:
```javascript
// 1. 从 FoodRecord 获取今日摄入和消耗
const todayStats = await FoodRecord.getTodayStats(req.user._id);

// 2. 从 ExerciseRoute 获取今日已开始/已完成的路线
const todayRoutes = await ExerciseRoute.find({
  user: req.user._id,
  $or: [
    { generatedAt: { $gte: today, $lt: tomorrow } },
    { startedAt: { $gte: today, $lt: tomorrow } },
    { completedAt: { $gte: today, $lt: tomorrow } }
  ]
});

// 3. 只统计已开始或已完成的路线
const activeRoutes = todayRoutes.filter(route => 
  route.status === 'started' || route.status === 'completed'
);

// 4. 累加路线消耗
activeRoutes.forEach(route => {
  routeCalories += route.actualCalories || route.estimatedCalories || 0;
});

// 5. 合并 FoodRecord 和 ExerciseRoute 的消耗
const totalExercise = todayStats.consume + routeCalories;
```

**重要**: 只有状态为 `started` 或 `completed` 的路线才会被计入统计！

### 2. StatsCard.vue - 用户累计统计

**数据来源**: `/api/stats/user-stats`

**获取的数据**:
- `streakDays`: 打卡天数（从 User 模型中获取）
- `totalCaloriesBurned`: 累计消耗热量（FoodRecord + ExerciseRoute）
- `totalExerciseMinutes`: 累计运动时长（分钟）
- `totalDistance`: 累计运动距离（公里）

**后端查询逻辑**:
```javascript
// 1. 从 FoodRecord 获取所有消耗记录
const allConsumeRecords = await FoodRecord.find({
  user: req.user._id,
  type: 'consume'
});

// 2. 从 ExerciseRoute 获取所有已开始/已完成的路线
const completedRoutes = await ExerciseRoute.find({
  user: req.user._id,
  status: { $in: ['started', 'completed'] }
});

// 3. 累加两个数据源的数据
totalCaloriesBurned = FoodRecord消耗 + ExerciseRoute消耗
totalExerciseMinutes = FoodRecord时长 + ExerciseRoute时长
totalDistance = FoodRecord距离 + ExerciseRoute距离
```

**重要**: 只有状态为 `started` 或 `completed` 的路线才会被计入累计统计！

### 3. GoalProgress.vue - 目标进度

**数据来源**: `/api/stats/goal-progress`

**获取的数据**:
- `calorie.progress`: 热量目标进度（根据目标取向计算）
- `exercise.progress`: 运动目标进度
- `overall.progress`: 综合进度

**后端查询逻辑**:
```javascript
// 1. 获取今日运动数据（同 daily-summary）
const activeRoutes = todayRoutes.filter(route => 
  route.status === 'started' || route.status === 'completed'
);

// 2. 根据用户目标取向计算目标
if (goalOrientation === 'lose') {
  dailyCalorieGoal = TDEE - 500; // 减重
  dailyExerciseGoal = 60; // 分钟
} else if (goalOrientation === 'gain') {
  dailyCalorieGoal = TDEE + 500; // 增重
  dailyExerciseGoal = 30; // 分钟
} else {
  dailyCalorieGoal = TDEE; // 维持
  dailyExerciseGoal = 45; // 分钟
}

// 3. 计算进度
const exerciseProgress = (totalExerciseMinutes / dailyExerciseGoal) * 100;
```

## 🔄 数据更新流程

### 用户点击"启动高德地图开始运动"按钮

1. **前端**: 调用 `startExercise(routeId)` API
   - API路径: `POST /api/route/:routeId/start`
   - 修复前: `/api/route/generate/:routeId/start` ❌ (404错误)
   - 修复后: `/api/route/:routeId/start` ✅

2. **后端处理**:
   - 更新路线状态: `generated` → `started`
   - 创建 FoodRecord 消耗记录（使用估算值）
   - 更新用户 totalStats（累计消耗、时长、距离）
   - 返回响应

3. **前端事件**:
   - 触发 `exercise-started` 事件
   - 通过 window 事件通知所有组件刷新

4. **组件刷新**:
   - `DailySummaryCard`: 调用 `refresh()` 方法
   - `StatsCard`: 调用 `refresh()` 方法
   - `GoalProgress`: 调用 `refresh()` 方法

## ⚠️ 重要说明

### 为什么数据没有更新？

1. **路线状态问题**: 
   - 路线刚生成时状态是 `generated`
   - 只有点击开始运动后，状态才会变成 `started`
   - 统计API只查询 `started` 或 `completed` 状态的路线
   - **如果 start 接口调用失败（404），状态就不会更新，统计就查不到数据**

2. **API路径错误**:
   - 修复前: `${API_ENDPOINTS.ROUTE.GENERATE}/${routeId}/start` 
   - 这会导致路径: `/api/route/generate/69451eefbc6be4119a8b2954/start` ❌
   - 修复后: `${API_ENDPOINTS.ROUTE.BASE}/${routeId}/start`
   - 正确路径: `/api/route/69451eefbc6be4119a8b2954/start` ✅

3. **数据查询逻辑**:
   - 统计API现在会先查询所有今日路线
   - 然后过滤出 `started` 或 `completed` 状态的路线
   - 只统计这些已开始/已完成的路线
