# 路线生成优化和数据库存储说明

## 完成的功能

### 1. ✅ 路线生成逻辑优化（参考初始优化方案）

根据优化方案文档实现了**四步决策系统**：

#### Step 1: 判断今天该不该保守（恢复日）
```javascript
isRecoveryDay = todayCalorieBalance < -300
```

#### Step 2: 根据用户主观强度给意图系数
```javascript
intensityIntentMultiplier = {
  relaxed: 0.6,    // 轻松
  moderate: 0.85,  // 微微累
  challenging: 1.05 // 明显累
}
```

#### Step 3: 计算今日推荐目标区间
- **情况A**：热量明显为负 & 用户想轻松 → 8-12分钟
- **情况B**：正常状态 → 12-20分钟
- **情况C**：状态好 & 用户愿意累一点 → 20-26分钟

#### Step 4: 最终兜底（下限值）
```javascript
ABSOLUTE_MIN = {
  duration: 5分钟,   // 最少5分钟
  calories: 20大卡   // 最少20大卡
}
```

### 2. ✅ 自动保存路线到数据库

创建了 `ExerciseRoute` 模型，自动保存以下信息：

- **路线基本信息**：运动类型、距离、时长、消耗
- **位置信息**：起点、终点坐标和地址
- **高德地图数据**：导航链接、周边POI、选中的POI
- **路线详情**：路线描述、亮点、安全提示、鼓励语
- **用户偏好**：路线风格、心情、强度偏好
- **状态管理**：generated → started → completed

### 3. ✅ 更新前端按钮使用实际导航链接

前端按钮现在使用后端返回的实际导航链接，而不是硬编码的链接。

### 4. ✅ 详细的终端日志输出

所有步骤都有详细的日志输出，包括：

- 📍 位置获取过程
- 📊 路线计算参数
- 🗺️ 高德地图API调用
- 💾 数据库保存操作
- 🏃 运动状态更新

## 数据库模型

### ExerciseRoute 模型

```javascript
{
  user: ObjectId,              // 用户ID
  sportType: 'walk'|'run'|'bike',
  distance: Number,           // 米
  duration: Number,           // 秒
  estimatedCalories: Number,  // 大卡
  startLocation: {
    lat, lng, address, city
  },
  endLocation: {
    lat, lng, poiName, poiType
  },
  navigationUrl: String,      // 高德导航链接
  routeDescription: String,
  routeHighlights: [String],
  safetyTips: [String],
  nearbyPOIs: [Object],
  selectedPOI: Object,
  status: 'generated'|'started'|'completed'|'cancelled',
  actualDistance: Number,     // 实际距离（完成时更新）
  actualDuration: Number,     // 实际时长（完成时更新）
  actualCalories: Number,     // 实际消耗（完成时更新）
  startedAt: Date,
  completedAt: Date,
  generatedAt: Date
}
```

## API 端点

### 1. 生成路线
```
POST /api/route/generate
```

**请求体**:
```json
{
  "preferences": {
    "preferredPostExerciseState": "moderate",
    "routeStyle": ["🏞️ Citywalk"],
    "mood": "放松"
  },
  "location": {
    "lat": 30.319,
    "lng": 120.030
  }
}
```

**响应**:
```json
{
  "success": true,
  "data": {
    "routeId": "路线ID",
    "navigationUrl": "高德导航链接",
    "routeSuggestion": {...},
    "navigation": {...}
  }
}
```

### 2. 开始运动
```
POST /api/route/:routeId/start
```

更新路线状态为 `started`，记录开始时间。

### 3. 完成运动
```
POST /api/route/:routeId/complete
```

**请求体**:
```json
{
  "actualDistance": 3500,    // 米（可选）
  "actualDuration": 1800,    // 秒（可选）
  "actualCalories": 150      // 大卡（可选）
}
```

更新路线状态为 `completed`，创建消耗记录。

## 工作流程

```
用户点击生成路线
    ↓
前端获取位置
    ↓
调用后端生成路线
    ├─ 优化计算（四步决策系统）
    ├─ 调用高德地图API
    ├─ 搜索周边POI
    └─ 生成实际路线
    ↓
自动保存到数据库（ExerciseRoute）
    ↓
返回路线ID和导航链接
    ↓
用户点击"开始运动"
    ├─ 调用 /api/route/:routeId/start
    └─ 打开高德地图导航
    ↓
用户完成运动
    └─ 调用 /api/route/:routeId/complete
        └─ 创建消耗记录（FoodRecord）
```

## 前端集成

### 使用实际导航链接

```typescript
// 生成路线后，保存导航链接
generatedRoute.value = {
  routeId: response.data.routeId,
  navigationUrl: response.data.navigationUrl,
  // ...
}

// 点击按钮时使用实际链接
const openAmap = async () => {
  if (generatedRoute.value?.navigationUrl) {
    // 更新状态为started
    await startExercise(generatedRoute.value.routeId)
    // 打开导航
    window.location.href = generatedRoute.value.navigationUrl
  }
}
```
