# 基于实际位置的路线生成说明

## 概述

已修复路线生成逻辑，现在系统会：
1. **解析位置信息**：调用逆地理编码获取城市信息
2. **搜索周边POI**：根据用户偏好搜索附近的景点、公园等
3. **基于实际POI生成路线**：选择合适的POI作为路线终点，而不是简单的坐标偏移

## 修复内容

### 1. 位置解析（逆地理编码）

**文件**: `src/routes/route.js`

在获取位置后，如果城市信息缺失，会自动调用高德地图逆地理编码API：

```javascript
// 如果城市信息是"未知"，调用逆地理编码获取城市信息
if (!location.city || location.city === '未知') {
  const regeoResult = await reverseGeocode(location.lat, location.lng);
  // 获取城市、省份、详细地址
}
```

### 2. 智能POI搜索

**文件**: `src/MCP/routeService.js`

根据用户路线偏好搜索合适的POI类型：

- **Citywalk/城市**：搜索公园、风景名胜、购物、餐饮
- **沿水路线**：搜索公园、风景名胜、水系
- **绿化多**：搜索公园、风景名胜

```javascript
// 根据路线偏好确定POI类型
if (routeStyle.some(s => s.includes('Citywalk'))) {
  poiTypes = '110000|150000|060000|070000'; // 公园、风景、购物、餐饮
}
```

### 3. 基于实际POI的路线生成

**文件**: `src/MCP/routeService.js`

不再使用简单的坐标偏移，而是：

1. **筛选合适的POI**：
   - 距离在建议距离的 0.5-1.5 倍范围内
   - 符合用户偏好的POI类型

2. **选择最佳终点**：
   - 选择距离最接近建议距离的POI
   - 如果找不到合适的POI，才使用距离计算

3. **生成实际路线**：
   - 从用户当前位置到选定的POI
   - 使用高德地图步行/骑行路线规划API

## 工作流程

```
获取用户位置
    ↓
逆地理编码获取城市信息
    ↓
根据用户偏好搜索周边POI
    ├─ Citywalk → 公园、风景、购物、餐饮
    ├─ 沿水路线 → 公园、风景、水系
    └─ 绿化多 → 公园、风景
    ↓
筛选合适的POI（距离、类型）
    ↓
选择最佳POI作为路线终点
    ├─ 找到合适的POI → 使用POI作为终点
    └─ 未找到 → 使用距离计算终点
    ↓
调用高德地图路线规划API
    ↓
生成实际路线和导航链接
```

## POI类型说明

高德地图POI类型编码：
- `110000`: 公园广场
- `150000`: 风景名胜
- `060000`: 购物服务
- `070000`: 餐饮服务
- `170000`: 水系

## 示例

### 用户位置：杭州（30.319, 120.030）
### 用户偏好：Citywalk

1. **搜索POI**：搜索半径5km内的公园、风景、购物、餐饮
2. **找到POI**：西湖、断桥、雷峰塔等
3. **筛选POI**：根据建议距离（如3.5km）筛选
4. **选择终点**：选择距离最接近的POI（如西湖）
5. **生成路线**：从当前位置到西湖的步行路线

## 优势

1. **真实路线**：基于实际POI生成，不是虚拟坐标
2. **符合偏好**：根据用户偏好选择合适的目的地
3. **距离合理**：选择的POI距离在建议范围内
4. **可导航**：生成的高德导航链接可以直接使用

## 注意事项

1. **POI搜索范围**：默认搜索半径5km，可根据需要调整
2. **距离筛选**：POI距离在建议距离的0.5-1.5倍范围内
3. **降级策略**：如果找不到合适的POI，会使用距离计算作为备选
4. **城市信息**：如果位置信息中没有城市，会自动调用逆地理编码获取

现在系统可以基于你的实际位置和周边真实POI生成路线了！
